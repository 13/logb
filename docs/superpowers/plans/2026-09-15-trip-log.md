# Trip Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Log trips (start/end counter, places, duration, battery) as a new activity category, show them on the timeline, and total them on the Info tab and in statistics.

**Architecture:** A trip is an activity with category `trip` and five new nullable columns; the end is the existing `counter_value`. Backend first (storage, validation, sync, export, search), then read endpoints (places, summary, monthly distance), then the form and timeline, then totals UI.

**Tech Stack:** Rust (axum, sqlx `Any` on SQLite + PostgreSQL), Svelte 5 runes, TypeScript, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-15-trip-log-design.md`

## Global Constraints

- Branch `build-trip-log`; never commit to `main`. Before every commit `git branch --show-current` must print `build-trip-log`. Stage only files the task changes.
- Portable SQL (SQLite and PostgreSQL); `CAST(... AS BIGINT)` for aggregates. PostgreSQL runs use a throwaway `postgres:17` container on port 55447 (`LOGB_TEST_DATABASE_URL=postgres://postgres:pg@127.0.0.1:55447/postgres`) that is always stopped afterwards.
- Category id `trip`; labels en "Trip", de "Fahrt". New columns exactly: `start_counter` INTEGER, `from_place` TEXT, `to_place` TEXT, `duration_minutes` INTEGER, `battery_used_pct` INTEGER, all nullable.
- Rules: a trip needs `counter_value` and `start_counter`; `0 <= start_counter <= counter_value`; places trimmed, max 80 characters, empty → null; `duration_minutes` 1–10080; `battery_used_pct` 0–100; a trip only on objects with `counter_unit` `km` or `mi`; on any other category the five fields must be absent or null. Distance = `counter_value - start_counter`, never stored.
- Every UI string in en and de; German number/date output asserted by pattern; dates via `fmtDate(iso, $dateFormat)`; date fields are `DateInput`.
- Playwright with project defaults (never `--workers`); targeted specs only (memory is limited); tests relying on `page.route` for cached API paths use `test.use({ serviceWorkers: 'block' })`.
- Disk: if `df -h /home` shows over 90% used, stop and report. Run the full `cargo test` at most once per task.
- Foreground commands (timeouts up to 600000 ms); never end a turn while one runs or to wait for a notification. Never weaken an existing assertion. Comments explain *why*.
