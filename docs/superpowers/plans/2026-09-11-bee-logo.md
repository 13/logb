# Bee Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the leftover *memto* **M** with a bee, rendered from one hand-authored SVG into every size the app needs, and put it on Login, Setup and the export archive.

**Architecture:** One drawing lives in `frontend/public/icon.svg`. A committed script renders the PWA PNGs from it, including the maskable variant, so the padded and unpadded assets can never drift. The manifest's icon list moves out of `vite.config.ts` into a module a test can import, which is what catches an edited SVG whose PNGs were never re-rendered.

**Tech Stack:** SVG, `rsvg-convert` (already installed locally; PNGs are committed so CI needs no image tooling), Svelte 5, Vite, vitest, Rust/axum with `rust-embed`.

## Global Constraints

- Palette is fixed — the bee uses colours already in the product: plate `#1f6f5f`, body `#f2b134`, head/stripes/stinger/antennae `#123c34`, wings white at 40–55% opacity.
- No new runtime dependency, frontend or backend. The frontend has zero runtime deps today; keep it that way.
- The top bar is deliberately out of scope: that row already holds a back button, the title, and the pending/dead outbox chips.
- PNGs stay committed artefacts, as they are today. CI must not need a rasteriser.
- `cargo clippy --all-targets --locked -- -D warnings` must pass; `npm run check` (svelte-check + tsc) must pass.
- `tests/openapi.rs` compares routes in both directions; this plan adds no route, so `docs/openapi.json` must be unchanged.

- [ ] **Step 4: Write the render script**

Create `frontend/scripts/render-icons.sh`, and `chmod +x` it:

```bash
#!/usr/bin/env bash
# Render every PNG the manifest needs from public/icon.svg.
#
# The PNGs are committed rather than built, so CI needs no rasteriser -- run this by hand
# whenever icon.svg changes, and commit what it produces. tests/pwa-icons.test.ts fails if a
# declared file is missing, but nothing can tell you a PNG is STALE, so re-run it every time.
set -euo pipefail
cd "$(dirname "$0")/.."

command -v rsvg-convert >/dev/null || { echo "needs rsvg-convert (librsvg)"; exit 1; }

svg=public/icon.svg
rsvg-convert -w 192 -h 192 "$svg" -o public/pwa-192.png
rsvg-convert -w 512 -h 512 "$svg" -o public/pwa-512.png

# The maskable variant: same bee, full-bleed plate, inset to the ~80% safe zone a launcher
# mask leaves visible. Built by slicing the bee out of icon.svg between its markers, so there
# is exactly one drawing in the repository.
bee=$(sed -n '/<!--bee-->/,/<!--\/bee-->/p' "$svg")
tmp=$(mktemp --suffix=.svg)
trap 'rm -f "$tmp"' EXIT
cat > "$tmp" <<EOF
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 64 64">
  <rect width="64" height="64" fill="#1f6f5f"/>
  <g transform="translate(6.4 6.4) scale(.8)">
$bee
  </g>
</svg>
EOF
rsvg-convert -w 512 -h 512 "$tmp" -o public/pwa-512-maskable.png

echo "rendered: pwa-192.png pwa-512.png pwa-512-maskable.png"
```

- [ ] **Step 5: Run it and check the output by eye**

Run: `cd frontend && ./scripts/render-icons.sh && ls -l public/*.png`
Expected: three PNGs written, all non-zero. Open `public/pwa-512-maskable.png` and confirm the bee sits clear of the edges — the stinger and antennae must not touch the border, because a circular mask will cut there.

- [ ] **Step 6: Move the icon list somewhere a test can read it**

Create `frontend/src/pwa-icons.ts`:

```ts
/** The manifest's icon list, kept here rather than inline in vite.config.ts so a test can
 *  import it and check every file it names actually exists. */
export const pwaIcons: { src: string; sizes: string; type: string; purpose?: string }[] = [
  { src: 'icon.svg', sizes: 'any', type: 'image/svg+xml', purpose: 'any' },
  { src: 'pwa-192.png', sizes: '192x192', type: 'image/png' },
  { src: 'pwa-512.png', sizes: '512x512', type: 'image/png', purpose: 'any' },
  { src: 'pwa-512-maskable.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
];
```

In `frontend/vite.config.ts`, add the import beside the others:

```ts

```

and replace the inline `icons: [ ... ]` array in the manifest with:

```ts

```

Note `pwa-512.png` drops from `'any maskable'` to `'any'` — it is not drawn with a safe zone, and claiming otherwise is what gets its edges clipped on a phone.

- [ ] **Step 3: Let the backend reach the embedded asset**

In `src/spa.rs`, change the `Assets` declaration so the export can read from it:


- [ ] **Step 4: Write the icon into the archive**

In `src/api/export.rs`, add above the export handler:

```rust
/// The app icon, taken from the embedded SPA build rather than a second copy in the tree.
///
/// Absent in a backend-only build (`frontend/dist/` empty, as in a plain `cargo test` before
/// the frontend has ever been built), which is not a reason to fail an export -- the archive is
/// simply without it, the same way a blob missing from disk is skipped below.
fn icon_bytes() -> Option<Vec<u8>> {
    crate::spa::Assets::get("icon.svg").map(|f| f.data.into_owned())
}
```

and inside the `spawn_blocking` closure, directly after the `data.json` entry is written:

```rust
        if let Some(icon) = icon_bytes() {
            w.start_file("icon.svg", deflate).map_err(|e| AppError::Internal(e.to_string()))?;
            w.write_all(&icon)?;
        }
```

- [ ] **Step 5: Run the tests to verify they pass**

Run: `cd frontend && npm run build && cd .. && cargo test && cargo clippy --all-targets --locked -- -D warnings`
Expected: both pass. The frontend build is required first: `icon_bytes` reads the embedded `frontend/dist/`, so without a build the new entry is absent and the test asserting it fails. If `cargo test` is run on a tree that has never built the frontend, that is the error you will see.

## Self-Review

**Spec coverage.** Every section maps to a task: the artwork and its colours, the four files, the one-drawing-several-renders rule and the manifest's maskable correction (Task 1); Login and Setup, plated (Task 2); the export archive reading the embedded asset with `Assets` becoming `pub(crate)` (Task 3). Both tests the spec asks for are present — the archive containing `icon.svg` (Task 3 Step 1) and every manifest-named icon existing with exactly one maskable (Task 1 Step 1).

The spec's exclusions hold: the top bar is untouched, no palette changes, and the artwork is not asserted pixel by pixel.

**Placeholder scan.** No TBDs, no "add error handling", no "similar to Task N" — Task 2 Step 4 spells out both files rather than saying "the same as above".

**Type consistency.** `pwaIcons` is defined in Task 1 and imported under that name by `vite.config.ts` and the test. `Logo.svelte`'s `size` prop is declared once and used with its default. `icon_bytes()` is defined and called in the same task. `Assets` is made `pub(crate)` in Task 3 Step 3, before its first use outside `spa.rs` in Step 4.

**Two ordering constraints the implementer must respect.** Task 3 depends on Task 1, because it reads `icon.svg` out of the built frontend — and it needs `npm run build` to have run at least once on that tree, or the new archive entry is absent and its test fails for a reason that looks nothing like the real cause. Task 2 also depends on Task 1, since `Logo.svelte` points at `/icon.svg`.

**One judgement call worth flagging.** `icon_bytes` returns `Option` and the export simply omits the entry when the embedded asset is missing, matching how a blob missing from disk is already skipped rather than failing the whole export. The alternative — failing the export because a logo is absent — would make a backend-only build unable to produce a backup, which is a far worse trade.
